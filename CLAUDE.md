# audiobook-generator

Personal tool (single user, Nia) that turns EPUBs into audiobooks. Upload an EPUB, narrate each chapter once with OpenAI TTS, cache the audio, then stream it in a mobile-friendly player or download it as an MP3. Mostly AO3 fanfic EPUBs, but any EPUB should work. It is used from a phone, often at night with the screen locked.

## Decisions already made (don't relitigate without asking)

- Next.js 15 (App Router, TypeScript), hosted on Vercel. Stay on Next 15 for now; Next 16 renames `middleware.ts` to `proxy.ts`.
- Input is EPUB upload. No live scraping of AO3 (fragile). A paste-a-link convenience that fetches AO3's EPUB download is a possible later add-on.
- Narration is OpenAI TTS by default (`gpt-4o-mini-tts`, switchable to `tts-1` via `OPENAI_TTS_MODEL`), Kokoro-82M through DeepInfra for about 1/16th the price, or ElevenLabs Flash v2.5 (`elevenlabs:flash:<voiceId>`, female premade voices, ~$60 per million characters, `ELEVENLABS_API_KEY`, untested against the real API). A "narrator" is a string: a plain voice name ("ballad") is the original OpenAI narrator; `deepinfra:kokoro:af_bella` is Kokoro. Each book has a default narrator in `voice`. It can be changed at any time (not while a job runs); chapters already narrated are pinned to the voice they were narrated in (`chapterVoices`), so only chapters narrated later use the new one. A range can also be read in another voice (`voice` on `POST /api/books/[id]/narrate`, `setChapterVoice`) without changing the default. Cost matters: it should be cheap, so audio is generated once per chapter and cached (`audioKey` in `lib/narration/tts.ts`).
- Streaming playback is the default; MP3 download is also available. Both come from the same cached file.
- Author's notes, chapter summaries and end notes are stripped before narration (`lib/epub.ts`). This must stay on by default. The upload form has a toggle.
- Storage is Cloudflare R2 (S3 API via `aws4fetch`) in production and `./.cache` locally (`lib/storage/storage.ts`). It replaced Vercel Blob, whose Hobby limits (2,000 advanced operations a month) were exhausted by polling and per-chunk writes. Keep operation counts low anyway: avoid tight polling and unneeded list calls.
- The deployed app is behind one shared password (`APP_PASSWORD`, checked in `middleware.ts`) so nobody else can spend the OpenAI credits.
- Single-user for now (one shared password, one shared library). Might become multi-user later. If so: real auth in `middleware.ts`, library/books keyed per user, resume position moved server-side, and per-user narration spend limits. Audio can stay shared since its keys are hashes of text and settings.

## Layout

`lib/` is grouped by domain: `lib/storage/` (R2/disk and the small records kept in it: library, keys, live, progress, settings, usage, speed, throttle, uploads), `lib/narration/` (narrating and serving audio: tts, text, mp3, http, repair, narration, reread, narrator, chaptervoice), `lib/pronunciation/`, `lib/providers/` (one file per TTS provider), `lib/client/` (browser API calls). Client-safe pure modules stay at the top of `lib/` (`narrators-shared`, `settings-shared`, `eta`, `listening`, `types`), plus `epub.ts` and `auth.ts`. Files below are named by their folder, e.g. `lib/storage/storage.ts`.

- `lib/epub.ts` EPUB parsing and note stripping. The riskiest code, since it is written against how AO3 structures EPUBs.
- `lib/narration/text.ts` splits chapters into chunks under OpenAI's 4096-character limit.
- `lib/narration/tts.ts` calls the narrator's provider, retries on 429/5xx, caches each chunk, and joins the MP3 pieces. Per-provider request shape and cache-key layout live in `lib/providers/` (one file each, registry in `index.ts`); client-safe facts (label, key env var, price, size check, whether the MP3 needs repair) are `PROVIDER_INFO` in `lib/narrators-shared.ts`. To add a provider: a `PROVIDER_INFO` row, voices/parsing in `narrators-shared.ts`, a file in `lib/providers/`, a registry line.
- `lib/narration/narration.ts` + `app/api/worker/[id]` + `app/api/books/[id]/narrate` background narration of a whole book: a job record in storage (with an optional `from`/`to` chapter range, so you can skip chapters you've already read), a worker that narrates ~250s then calls itself again.
- `app/api/uploads` + `lib/storage/uploads.ts`: EPUBs over ~4 MB are PUT by the browser straight to R2 via a signed URL (Vercel caps request bodies at ~4.5 MB), then `POST /api/books` with `{uploadKey}` reads, parses and deletes the temporary file. Needs a CORS rule on the bucket (see README).
- Job controls: a job can be `running`, `paused`, `done`, `cancelled` or `error`. `PATCH /api/books/[id]/narrate {action: pause|resume|cancel}`; the worker checks for a pause/cancel between chunks (at most every 8 s, `shouldStop` in `synthesizeChapter`) and re-reads the job before saving progress so it never overwrites a pause. `jobs/active.json` lists books with a running/paused/failed job; `GET /api/queue` + `app/queue/page.tsx` (the Queue tab) read it, so no storage listing is needed.
- `lib/eta.ts` (client-safe) + `lib/storage/speed.ts`: narration speed per provider is measured by the worker (characters synthesized / wall time, flushed once per worker run to `stats/speed.json`, read by `/api/speed` and `/api/queue`) and turned into "about N min" estimates. It says "time not known yet" until ~3,000 characters have been measured.
- Pronunciations: `lib/pronunciation/pronunciation.ts` (pure) swaps whole words for how to say them just before narration (`spokenText`; `audioKey` hashes the spoken text, and with no lines the text is untouched so existing cache keys are unchanged). A book has its own `pronunciations` plus `pronList`, a copy of a named list made at upload (`lib/pronunciation/pronlists.ts`, `pronlists.json`, one list can be `auto`); own lines win. Narrated chapters are pinned in `book.frozen` to the lines they were narrated with, so editing lines or "Update from list" never makes paid-for audio unready; `renarrate` (per-chapter checkboxes with prices) and `lib/narration/reread.ts` (`POST /api/books/[id]/reread`, a re-read button on each narrated chapter in the player) drop the pin, delete the chapter's audio and un-narrate it; both show the cost first and refuse while a job runs. Editing is refused while a job runs. UI: `app/book/[id]/pronunciation`, `app/pronunciations` (lists), selector on the add page.
- In-app dialogs: `components/Dialog.tsx` (`useDialog()`: `confirm`, `notify`, and `reread`, the single form for narrating a chapter again with a pronunciation list and/or voice, ending in a "Narrate" button). Never use `window.confirm`/`alert`. Call `useDialog()` with the other hooks at the top of a component, before any early return.
- Per-chapter voices: `book.chapterVoices` (`lib/narration/chaptervoice.ts` `voiceFor`) overrides the fic's `voice` for single chapters; switching the fic's voice pins already-narrated chapters to their old voice. Everything that builds an `audioKey` must use `voiceFor(book, index)`. `lib/narration/reread.ts` does the re-read (`rereadChapters`: list, voice, "whole fic from now on", for one or several chapters). Several chapters are re-read by selecting them on the chapter picker; the form then clears their audio and starts a background job with an explicit `Job.chapters` list (`remainingChapters` in `lib/narration/narration.ts`), so the gaps between them are not narrated.
- `app/api/pronounce` + `components/HearButton.tsx`: a "Hear" button next to each pronunciation line plays the respelling in a chosen narrator (a few words, kept so hearing it again is free), so a respelling can be tried before narrating a chapter.
- `lib/storage/keys.ts` (`keys/<bookId>.json`): where each narrated chapter's audio is, so playing a narrated chapter (audio route `?prepare=1` and plain) never reads the whole book's text. Written when a chapter is narrated or first played (backfill), cleared when it is re-read or re-narrated and when the EPUB is re-uploaded. The player skips `?prepare=1` for chapters the library lists as narrated. `?progress=1` keeps the parsed book for 30 s. Anything that un-narrates a chapter must call `clearKeys`, and the player must drop its `readyRef` entry.
- Play through the queue: pressing play on a chapter that isn't narrated starts a one-chapter background job (`POST /narrate {chapters:[n], onlyIfIdle:true}`, refused with 409 if the book already has a running/paused job) and the player polls `?progress=1` (plus the job status every 6 s) until the audio exists (`prepareViaQueue` in `PlayerProvider`). It keeps narrating if the tab closes and shows in the Queue; moving to another chapter cancels the job it started. If a job is already running, or starting one fails, the player narrates directly as before (`prepare`), which is also how prefetching the next chapter works.
- `lib/storage/live.ts` (`jobs/live.json`): narrations started by pressing play, so the Queue shows everything being narrated, not only background jobs.
- `lib/storage/library.ts` records which chapters are narrated for the library list.
- `lib/narration/mp3.ts` joins MP3 pieces: strips every ID3 tag and Xing/Info frame (Kokoro via DeepInfra puts one at the start of every sentence stream), and for variable-bitrate audio writes one correct Xing header (frame count, size, seek table) so players know the true length and can seek; `?inspect=1` on the audio route reports a saved file's structure. `lib/narration/http.ts` serves audio with HTTP Range support. iOS Safari needs this to play and seek.
- `app/api/audio/[id]/[chapter]/route.ts` (the redirect is `no-store` and chapter audio is cached only 10 minutes, because a chapter can be rebuilt or re-read under the same key; never mark chapter audio immutable) has four modes: `?progress=1`, `?prepare=1` (narrate if needed, no bytes), `?download=1` (proxied named MP3), and plain (307 redirect to a short-lived signed R2 URL so the phone streams from the CDN; served from disk locally).
- `lib/narrators-shared.ts` (client-safe) narrator ids, Kokoro voices, prices per million characters. `lib/narration/tts.ts` builds the request per provider and shares retries/checks. `lib/narration/narrator.ts` changes a book's narrator (`changeNarrator`) or gives chosen chapters their own voice (`setChapterVoice`). **Never change `audioKey` for plain voice names**: `tests/cachekeys.test.ts` pins the real keys (audio already paid for lives under them); new narrators use a separate versioned layout.
- `lib/listening.ts` pure rules for "Start listening" (begins at the chosen range, not chapter 1), the confirm-before-narrating prompt, range-limited prefetch/auto-advance. `components/AppChrome.tsx` shows the prompt; Settings can turn it off (device-local).
- `lib/storage/usage.ts` monthly dollar budget (`MONTHLY_BUDGET_USD`, default $30, priced per narrator) plus an optional `MONTHLY_CHAR_LIMIT`, checked before every provider call. The counter is batched: `recordUsage` adds to memory and `flushUsage()` writes once per chapter (`synthesizeChapter` does it), as a read-add-write; keep storage operations low. `lib/storage/throttle.ts` locks a login address out for 15 minutes after 5 wrong passwords.
- `components/PlayerProvider.tsx` the one persistent `<audio>` element and all playback logic (chapter loading, auto-advance, sleep timer, resume, lock-screen controls, background-job polling). It lives in the root layout so audio keeps playing while screens change. Pieces that don't need the audio element live in `components/player/`: `types.ts`, `store.ts` (device-local settings), `narration.ts` (requests to narrate a chapter, no React), and the hooks `useBackgroundJob`, `useSleepTimer`, `useMediaSession`, `useLibrary`, `useSavedPosition`. Chapter loading, auto-advance and the audio events still live in `PlayerProvider` because they share its refs.
- `components/AppChrome.tsx` the bottom dock (mini player stacked on the tab bar, one fixed bar as wide as the page), mini player, dim layer and bedside mode. `components/Icon.tsx` is the line-icon set.
- Screens: `app/page.tsx` library, `app/add`, `app/book/[id]` player, `app/book/[id]/narrating`, `app/settings`. The look is called Lamplight (tokens in `app/styles/tokens.css`; `app/globals.css` only imports the per-area files in `app/styles/`, in an order that matters): warm near-black, cream text, candle amber, Fraunces + Hanken Grotesk. No purple, no pure white, no emoji icons.
- `lib/client/api.ts` the browser's typed calls to the server's JSON API (`ApiError` carries the server's own message; "soft" functions return null or a default instead of throwing). Prefer adding a function there over a new inline `fetch`. The player's narration and job calls are in `components/player/`, and the audio element's URLs are built where it is used. `components/NarratorOptions.tsx` is the one place that lists narrators inside a `<select>` (price, "needs a key", current).
- `lib/storage/settings.ts` / `lib/settings-shared.ts` (server vs client-safe) and `lib/storage/progress.ts` are small server-side records (settings, listening position). Each book stores its own `voice`, fixed when first added.

## Working rules

- Run `npm test` and `npm run typecheck` before pushing. Add a test when fixing a parser bug.
- Never commit secrets. `.env.local` is gitignored; `.env.example` lists the variables.
- Work on a branch and open a PR rather than pushing to `main`.
- `tests/player.test.ts` runs the real `PlayerProvider` in jsdom (Testing Library) with a fake `fetch` and a stubbed audio element: playback, resume, the confirm-before-narrating flow, auto-advance, sleep timer, lock-screen controls and the background job. Run it after touching `components/PlayerProvider.tsx` or `components/player/`. It can't catch real-browser or iOS audio behavior.
- `npm run test:e2e` (Playwright, `e2e/`) builds the app, starts it with a fake OpenAI server (`e2e/fake-openai.mjs`, silent MP3s) and an empty cache, and clicks through settings, add, shelf, narrating, queue, pronunciation and the player on a phone-sized Chromium. Locally set `E2E_CHROMIUM` to a Chromium binary if `playwright install` isn't possible. `.github/workflows/ci.yml` runs typecheck, unit tests and the browser tests on every PR. Add a spec in `e2e/app.spec.ts` when you add a screen.
- Never call the real OpenAI API in tests. Point `OPENAI_BASE_URL` at a local mock.
- Keep the UI usable one-handed on a phone: big tap targets, dark theme, no horizontal scrolling.

## Known gaps

- Kokoro/DeepInfra has been tested only against a local fake server (request shape from DeepInfra's OpenAI-compatible docs). Real voice names, request limits per chunk, and sound quality are unverified until a real key is used; the Kokoro voice list comes from the model card and DeepInfra may reject some.
- The Kokoro price ($0.99 per million characters) is the figure shown on DeepInfra's Kokoro page; DeepInfra's own pages have disagreed. Free tiers are not modelled, so cost estimates are an upper bound.
- Direct-to-R2 EPUB upload (signed PUT URL + bucket CORS) is tested only against an in-memory stand-in, not real R2.
- The audio redirect to R2 (and Range playback through it on iOS Safari) hasn't been tried on real Vercel/phone. The `?prepare=1` flow avoids a cross-origin fetch on purpose; the audio element itself follows the redirect.
- The Lamplight screens were checked with screenshots only against a fake OpenAI server. Playing real audio, the sleep timer, bedside mode and auto-advance haven't been exercised in a real browser or on a phone.
- Paste-an-AO3-link is a disabled placeholder (scraping is a standing decision to avoid).
- Background narration (self-chaining worker) works locally against a mock but hasn't run on real Vercel. Check that the worker can call its own production URL (Deployment Protection off) and that a >250s book hops correctly.
- Note-stripping has been checked against one real AO3 download ("Download > EPUB"). AO3 builds its EPUBs with Calibre, so they turn note headings into plain `<p>` labels and name the files `*_split_000.xhtml` instead of preface/afterword. Other AO3 works may differ (series, anonymous works, many chapters). If an EPUB leaks notes into the narration, fix `lib/epub.ts` and add that case to `tests/epub.test.ts`.
- iOS lock-screen playback was checked on a real phone (2026-10-23: plays with the screen locked). Auto-advance between chapters and the sleep timer on a phone are still unchecked.
- Chapter narration can take a minute or more the first time. Long chapters are narrated chunk by chunk (`synthesizeChapter` in `lib/narration/tts.ts`): each chunk is cached on its own, and if the ~200s budget runs out the audio route returns `202 {ready,total}` and the player retries, resuming where it stopped. The 202/retry flow hasn't been tried against real Vercel or a real phone.
